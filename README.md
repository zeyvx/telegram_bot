# Telegram Support Bot

Telegram-бот службы поддержки для регистрации пользователей, создания обращений и просмотра истории заявок.

Проект разработан на Python с использованием асинхронного фреймворка aiogram и асинхронной работы с SQLite.

## Возможности

### Пользователь

- Регистрация через отправку контакта Telegram
- Выбор категории обращения:
  - Техническая проблема
  - Оплата
  - Доставка
  - Заказ
  - Другое
- Создание заявки с текстовым описанием проблемы
- Прикрепление документа или фотографии
- Возможность пропустить добавление файла
- Просмотр собственных заявок
- Навигация между заявками с помощью inline-кнопок
- Просмотр категории, описания и текущего статуса заявки

### Администратор

Административная часть проекта находится в разработке.

Планируется добавить:

- просмотр новых заявок;
- просмотр всех обращений;
- изменение статуса заявки;
- обработку заявок администраторами.

## Описание основных компонентов

### `Handlers/`

Обработчики сообщений, команд и callback-запросов Telegram.

### `Handlers/user/`

Пользовательская часть бота.

- `start.py` — регистрация пользователя и отображение главного меню.
- `requests.py` — создание заявок, добавление вложений и просмотр истории обращений.

### `Handlers/admin/`

Административная часть проекта.

Находится в разработке.

### `database/`

Работа с базой данных SQLite.

- `database.py` — создание и инициализация таблиц базы данных.
- `dao/users_dao.py` — функции для работы с пользователями и заявками.

### `keyboards/`

Клавиатуры Telegram-бота.

Содержит inline- и reply-клавиатуры для взаимодействия с пользователем.

### `services/`

Слой бизнес-логики приложения.

Будет использоваться для отделения логики приложения от Telegram handlers и работы с базой данных.

### `states/`

FSM-состояния, используемые в сценариях бота.

Сейчас содержит состояния процесса создания заявки:

```text
category
    ↓
request
    ↓
file
```

## База данных

Проект использует SQLite.

### Таблица `users`

Хранит зарегистрированных пользователей.

| Поле | Описание |
|---|---|
| `user_id` | Telegram ID пользователя |
| `phone` | Номер телефона пользователя |

Номер телефона является уникальным.

### Таблица `requests`

Хранит обращения пользователей.

| Поле | Описание |
|---|---|
| `id` | Уникальный ID заявки |
| `user_id` | ID пользователя |
| `category` | Категория обращения |
| `request` | Описание проблемы |
| `file_id` | Telegram ID прикреплённого файла |
| `status` | Текущий статус заявки |

При первом запуске бота необходимые таблицы создаются автоматически.

## Установка

### 1. Клонирование репозитория

```bash
git clone https://github.com/zeyvx/telegram_support_bot.git
cd telegram_support_bot
```

### 2. Создание виртуального окружения

#### Windows

```bash
python -m venv .venv
```

Активация:

```bash
.venv\Scriptsctivate
```

#### Linux/macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Настройка переменных окружения

Создайте файл `.env` в корне проекта на основе `.env.example`.

Пример:

```env
BOT_TOKEN=your_bot_token
OPERATOR_PHONE=your_operator_phone
```

Файл `.env` не должен добавляться в GitHub.

### 5. Запуск

```bash
python main.py
```

## Сценарий работы пользователя

Пользователь → `/start` → Проверка регистрации

Если пользователь зарегистрирован:

Пользователь → Главное меню

Если пользователь не зарегистрирован:

Пользователь → Отправка контакта → Регистрация → Главное меню

Создание заявки:

Отправить заявку → Выбор категории → Описание проблемы → Документ / фото / пропуск → Сохранение заявки → Заявка успешно создана

## Архитектура проекта

Проект постепенно развивается в сторону разделения ответственности между компонентами.

```text
Telegram Update
      ↓
   Handler
      ↓
   Service
      ↓
     DAO
      ↓
   Database
```

Каждый слой отвечает за свою часть приложения:

- `Handlers` — взаимодействие с Telegram;
- `Services` — бизнес-логика;
- `DAO` — работа с базой данных;
- `Database` — инициализация базы и таблиц.

## Git-ветки

Для разработки используются отдельные ветки.

Пример:

```text
main
│
└── feature/admin-panel
```

`main` содержит стабильную версию проекта.

Новые функции разрабатываются в отдельных feature-ветках и после проверки объединяются с `main`.
