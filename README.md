# Telegram Support Bot

Telegram-бот службы поддержки для регистрации пользователей, приёма обращений и их обработки администраторами.

Проект написан на Python с использованием асинхронного фреймворка **aiogram 3** и асинхронной работы с **SQLite** (aiosqlite).

## Возможности

### Пользователь

- Регистрация через отправку контакта Telegram
- Выбор категории обращения:
  - Техническая проблема
  - Оплата
  - Доставка
  - Заказ
  - Другое
- Создание заявки с текстовым описанием проблемы
- Прикрепление документа или фотографии (или пропуск этого шага)
- Просмотр собственных заявок с постраничной навигацией (inline-кнопки)
- Просмотр категории, описания и текущего статуса заявки
- Быстрая связь с оператором и раздел FAQ (заглушка)

### Администратор

Панель администратора уже частично реализована:

- Отдельное меню, которое видит только пользователь из списка админов
- Просмотр новых заявок (статус `Новая`) с постраничной навигацией
- Взятие заявки в работу (кнопка «Взять в работу» → статус меняется на `В работе`, заявка закрепляется за админом)
- Просмотр своих заявок, взятых в работу («Мои заявки»)

В разработке:

- просмотр всех заявок («Все заявки»)
- статистика по заявкам
- изменение статуса на «Закрыта» / «Отклонена»
- ответ пользователю прямо из панели администратора

## Описание основных компонентов

### `Handlers/`

Обработчики сообщений, команд и callback-запросов Telegram, разделённые на пользовательскую и административную часть.

### `database/`

- `database.py` — создание и инициализация таблиц базы данных при первом запуске.
- `dao/users_dao.py` — регистрация пользователей, создание заявок, получение заявок конкретного пользователя.
- `dao/admins_dao.py` — получение всех/новых заявок, заявок, взятых конкретным админом, и логика взятия заявки в работу.

### `keyboards/`

Inline- и reply-клавиатуры бота: главное меню пользователя, выбор категории обращения, меню администратора и переиспользуемая пагинация (`navigation.py`), которая умеет как листать список заявок, так и добавлять кнопку «Взять в работу».

### `services/`

Слой бизнес-логики, отделяющий Handlers от прямой работы с данными. Пока используется в основном для форматирования текста заявок; постепенно будет расширяться.

### `states/`

FSM-состояния сценариев бота:

```
Регистрация:
waiting_contact

Создание заявки:
category → request → file
```

## База данных

Проект использует SQLite (файл `database.db`, создаётся автоматически при первом запуске).

### Таблица `users`

| Поле      | Описание                    |
| --------- | ---------------------------- |
| `user_id` | Telegram ID пользователя (PK) |
| `phone`   | Номер телефона (уникальный)  |

### Таблица `requests`

| Поле       | Описание                                          |
| ---------- | -------------------------------------------------- |
| `id`       | Уникальный ID заявки (PK, автоинкремент)           |
| `user_id`  | ID пользователя, создавшего заявку                 |
| `category` | Категория обращения                                |
| `request`  | Описание проблемы                                  |
| `file_id`  | Telegram file_id прикреплённого документа/фото     |
| `status`   | Текущий статус (`Новая`, `В работе`, ...)          |
| `admin_id` | ID администратора, взявшего заявку в работу        |

## Установка

### 1. Клонирование репозитория

```
git clone https://github.com/zeyvx/telegram_support_bot.git
cd telegram_support_bot
```

### 2. Создание виртуального окружения

**Windows**

```
python -m venv .venv
.venv\Scripts\activate
```

**Linux/macOS**

```
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установка зависимостей

```
pip install -r requirements.txt
```

### 4. Настройка переменных окружения

Создайте файл `.env` в корне проекта на основе `.env.example`:

```
BOT_TOKEN=your_bot_token
OPERATOR_PHONE=your_operator_phone
```

Файл `.env` не должен попадать в git (уже добавлен в `.gitignore`).

### 5. Настройка администраторов

Список ID администраторов сейчас задаётся прямо в `config.py`:

```python
ADMINS = [8539830854]
```

Замените значение(я) на Telegram ID реальных администраторов бота.

> В планах — вынести список администраторов в переменные окружения или в базу данных, чтобы не редактировать код.

### 6. Запуск

```
python main.py
```

## Сценарий работы пользователя

```
/start
   │
   ├── Пользователь уже зарегистрирован → Главное меню
   │
   └── Не зарегистрирован → Отправка контакта → Регистрация → Главное меню
```

Создание заявки:

```
Отправить заявку → Выбор категории → Описание проблемы
   → Документ / фото / "Пропустить" → Заявка сохранена
```

## Сценарий работы администратора

```
/start (ID есть в config.ADMINS)
   │
   └── Панель администратора
         ├── Новые заявки → пагинация → "Взять в работу"
         ├── Мои заявки (взятые в работу)
         ├── Все заявки        (в разработке)
         └── Статистика        (в разработке)
```

## Архитектура проекта

Проект придерживается разделения ответственности между слоями:

```
Telegram Update
      ↓
   Handler
      ↓
   Service
      ↓
     DAO
      ↓
   Database
```

- `Handlers` — приём и обработка апдейтов Telegram
- `Services` — бизнес-логика и форматирование
- `DAO` — работа с базой данных
- `Database` — инициализация базы и таблиц

## Git-ветки

Для разработки новых функций используются отдельные ветки:

```
main
│
└── feature/...
```

`main` содержит стабильную версию проекта. Новые функции разрабатываются в feature-ветках и после проверки объединяются с `main`.
